It provides flexibility by allowing easy configuration of various connection parameters, facilitating seamless switching between different databases or server environments. The engine's built-in error handling mechanisms ensure robustness and stability in the face of database-related issues.

We will use one popular Python library, namely `SQLAlchemy` to create a database engine and interact with databases.

## Source Data from Excel File

In the next few steps, what I'm going to do is: 

- Read an excel file and match 5 sheets out of 7 sheets with the pattern `Orders *`. 
- While reading the sheets, I'll append the sheets data one after another and store the concatenated data into a variable called "df." 
- The database system as well as I prefer a unified format for column names. 
- Hence, I removed all the whitespaces in column names and replaced them with underscores (`_`). 
- I also converted all the letters into lowercase. 

Thus, the source data is now ready for inserting into databases.

```python
path = os.getcwd()
subdirectory = 'data'

file = os.path.join(path, subdirectory, 'superstore_2016-2020_data.xlsx')
file
```

Our Excel file can have multiple sheets, all of which we don't need to combine always. Hence, we are selecting only the sheets whose names match the pattern `Orders *`, as these are the sheets that contain yearly order data.

```python
excel_file = pd.ExcelFile(file)

sheets = excel_file.sheet_names
r = re.compile('Orders *')
selected_sheets = list(filter(r.match, sheets))

selected_sheets
```

Reading and concatenating selected sheets data one after another. Saving the final result into dataframe `df`.

```python
li = []

for sheet in selected_sheets:
    data = excel_file.parse(sheet)
    data['sheet_name'] = sheet.split("\\")[-1]
    li.append(data)

df = pd.concat(li, axis = 0, ignore_index = True)
df.head(2)
```

Reformatting column names

```python
for col in df.columns:

```

## Write Data into Databases

Now that we have read data from the source, it's time to write it into databases. Below is a general function that will be used to write dataframe `(df)` data into databases.

The function accepts `database engine name`, `table name`, and `schema name` as parameters where `schema name` is an optional parameter as certain databases don't follow schema conventions, e.g., MySQL.

```python
def write_table_data(db_engine_name, table_name, schema_name = None):
    df.to_sql(
        name = table_name,
        schema = schema_name,
        con = db_engine_name,
        if_exists = 'replace',
        index = False,
        method = 'multi',
        chunksize = 1000,
        dtype = {
            'order_date': sqa.types.Date,
            'ship_date' : sqa.types.Date,
            'sales': sqa.types.Float,
            'quantity': sqa.types.Integer,
            'discount': sqa.types.Float,
            'profit': sqa.types.Float
        }
    )

    print('Currnet Database Engine: {0}'.format(db_engine_name))
    
    if schema_name is not None:
        print('\nSuccessfully inserted {0} rows in schema/table: {1}.{2}!'.format(df.shape[0], schema_name, table_name))
    else:
        print('\nSuccessfully inserted {0} rows in table: {1}!'.format(df.shape[0], table_name))
```

## Read Data from Databases

The source data is in databases now. Let's read data using a custom SQL query from each of the databases.

Below is a general function that accepts `database engine name`, `table name`, and `schema name` as parameters, where `schema name` is an optional parameter as certain databases don't follow schema conventions, e.g., MySQL.

Hence we are using two different query strings, i.e., `query_1` (for databases that follow schema convention) and `query_2` (for databases that don't follow schema convention). We are handling this using `if-else` at the bottom section of the function.

```sql
def read_table_data(db_engine_name, table_name, schema_name = None):
    query_1 = """
        SELECT
            region,
            category,
            sub_category,
            SUM(sales) total_sales,
            SUM(profit) total_profit,
            AVG(quantity) avg_quantity,
            AVG(discount) avg_discount

        FROM {0}.{1}

        GROUP BY 
            region,
            category,
            sub_category

        HAVING SUM(profit) < 0;

    """.format(schema_name, table_name)
    
    
    query_2 = """
        SELECT
            region,
            category,
            sub_category,
            SUM(sales) total_sales,
            SUM(profit) total_profit,
            AVG(quantity) avg_quantity,
            AVG(discount) avg_discount

        FROM {0}

        GROUP BY 
            region,
            category,
            sub_category

        HAVING SUM(profit) < 0;

    """.format(table_name)
    
    
    if schema_name != None:
        df = pd.read_sql(sql = query_1, con = db_engine_name)
        print('Currnet Database Engine: {0}\n'.format(db_engine_name))
        print('Successfully read {0} rows from schema/table: {1}.{2}!\n'.format(df.shape[0], schema_name, table_name))
    
    else:
        df = pd.read_sql(sql = query_2, con = db_engine_name)
        print('Currnet Database Engine: {0}\n'.format(db_engine_name))
        print('Successfully read {0} rows from table: {1}!\n'.format(df.shape[0], table_name))
        
    return df
```

In the SQL query above, we are taking sales, profit, quantity, and discount by region, category, and sub-category for those orders only where the company incurred a loss (the profit amount is negative '-ve').
